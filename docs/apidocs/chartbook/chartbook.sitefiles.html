chartbook.sitefiles#

The build that writes a site: the writer’s pages, and the files beside them.

A site is a pure function of an index and the files the index names. The Sphinx writer (:mod:chartbook.writers.sphinx) renders the pages from the records; this module copies the files themselves into the Sphinx tree — charts, notebooks, notes, data downloads, the theme’s own files and a pipeline’s own site pages — driven by the same index, and :func:write_site puts the two together. Nothing here reads a manifest to decide what to copy: the index says what the site has.

chartbook.sitefiles.copy_files(plan: Iterable[tuple[pathlib.Path, pathlib.Path]]) → None[source]#

Copy each file to where the plan says, making the folders on the way.

chartbook.sitefiles.copy_plan(index: dict, docs_build_dir: pathlib.Path, enable_data_download: bool = False, skip: Iterable[str] = (), reused: Iterable[str] = (), with_notes: bool = True) → list[tuple[pathlib.Path, pathlib.Path]][source]#

Where each file the index names goes under the Sphinx tree, as (source, destination) pairs.

A chart’s HTML goes to cb/download_chart/<slug>/<name>.html and to _static/<slug>/<name>.html (the page embeds the latter); a notebook to cb/notebooks/<slug>/<its file name>; a note to cb/<name>.md; and, when downloads are enabled, a dataframe that is one file to cb/download_dataframe/<slug>/<name>.parquet, or the ending of its format (<name>.csv.gz; :func:download_link). A table, a query or a folder of parts has no file to offer. A files asset’s preview image goes to _static/<slug>/files/<name>.<ending>, where its page shows it.

Parameters:

  • skip – Pipelines the build leaves out: nothing of theirs is copied.

  • reused – Pipelines an incremental build keeps from an earlier one: their charts, notebooks and downloads stay as they are, but their notes are copied again, since the front page that lists them is written on every build and the tree is synced to what was written.

  • with_notes – Whether notes are copied at all: the pipeline theme’s front page lists them; a catalog has no page that does.

chartbook.sitefiles.copy_site_pages(index: dict, docs_build_dir: pathlib.Path) → None[source]#

Copy a pipeline’s own site pages (its site_dir) to the root of the Sphinx tree.

Every file under the folder, but index_toc.md at its root, which the writer merges into the front page instead. A pipeline site’s one pipeline supplies them; the catalog theme has no front page that lists them, so a catalog copies none.

chartbook.sitefiles.copy_theme_files(docs_src_dir: pathlib.Path, docs_build_dir: pathlib.Path, charts: bool = True, templates: bool = True) → None[source]#

Copy the theme’s own files to the root of the site tree, and its charts listing under cb/.

Everything under the theme’s docs_src but what the writer renders and the generated folders (:data:THEME_FILES_NOT_AT_ROOT); the folder structure is kept, and only file contents are copied.

Parameters:

  • charts – Whether the theme’s static charts.md goes under cb/; not when the writer renders that page itself.

  • templates – Whether the theme’s _templates folder is copied; Sphinx reads its HTML templates from there, MkDocs would render them as pages.

chartbook.sitefiles.download_link(record: dict) → dict[source]#

What a dataframe’s page offers for download: the file’s name in the site, and its format’s.

download_file is <name> with the ending of the file’s format, its own when it has one (rates.csv.gz) and the format’s first otherwise (rates.parquet); download_format is what the page calls it, Parquet or CSV.

chartbook.sitefiles.downloadable(record: dict) → bool[source]#

Whether a dataframe is one file the build copies for download: its page links it only then.

A table, a query, a folder of parts and a glob have no one file to offer, and one not built has none yet.

chartbook.sitefiles.ensure_notebook_titles(index: dict, docs_build_dir: pathlib.Path, skip: Iterable[str] = ()) → None[source]#

Give each copied notebook a title cell if its first cell is not a heading.

Sphinx needs a title for every document, and skips one without saying so. The title is the notebook’s name, or its key.

chartbook.sitefiles.not_built(record: dict) → bool[source]#

Whether a record is of a declared file that is not there: not built yet.

A file that is there and could not be read has no hash either, and is not this: copying it fails, and says why.

chartbook.sitefiles.write_not_built(index: dict, docs_build_dir: pathlib.Path, skip: Iterable[str] = ()) → None[source]#

Put a short file saying “not built yet” where each unbuilt chart and notebook would go.

A pipeline that has built nothing yet is rendered all the same (see build_docs.generate_docs), and its pages link to its charts and notebooks: each link then goes to this, rather than nowhere. The index has the record and no hash, so its provenance panel says “not built” too.

chartbook.sitefiles.write_site(docs_build_dir: pathlib.Path, base_dir: pathlib.Path, pipeline_theme: str = 'pipeline', docs_src_dir: Optional[pathlib.Path] = None, size_threshold: float = 50, skip_pipelines: Optional[Iterable[str]] = None, reuse_pipelines: Optional[Iterable[str]] = None, code_times: Optional[dict] = None, hash_cache=None, built_index: Optional[dict] = None) → dict[source]#

Write the Sphinx tree of a site: the index first, then its pages and files.

The index is built once, before any page, so that every page is a reader of it and says what it says. Then the writer renders a page for every record of a pipeline this build generates — a pipeline the build skips, or an incremental build keeps, has none written — plus the catalog’s own pages, and the files the index names are copied beside them: charts, notebooks, notes, downloads, the theme’s files and, in the pipeline theme, the pipeline’s own site pages. A chart or notebook that is not built yet gets a short file saying so in its place.

Parameters:

  • code_times – Code-change times already known, by pipeline ID (see manifest.apply_code_change_times). Others are worked out here.

  • built_index – The index, when the caller built it already.

Returns:

The index the site was written from.
