chartbook.resolve#

Name resolution: turn a reference into a typed location.

Everything that maps a name to a place — assets.path(), data.path(), data.load(), data.get_data_path(), chartbook path — calls

func:

resolve and gets back a :class:Location. What to do with a location is the caller’s business; looking the name up is not, so there is exactly one place where names are resolved.

A reference is parsed by :mod:chartbook.refs, which accepts the whole grammar. This module decides which references can be resolved yet, and refuses the rest as reserved, not invalid.

Today a location is always a :class:FileLocation. The data-access design (docs_src/design/data-access.md) adds table- and query-backed dataframes as further kinds, which is why load() and path() each call the resolver rather than one calling the other: a table has no path, but it can still be loaded.

Three forms of reference resolve today:

  • a local reference — name or kind/name — against the chartbook.toml enclosing the caller. It resolves live: to the path the manifest declares, which is the file you are working on. The raw file is read and nothing else, so this is cheap, offline, and does not care whether the asset has been built yet;

  • a cross-pipeline reference — pipeline:name — to an asset of a pipeline that [dependencies] declares. It resolves pinned: through chartbook.lock to the copy in the store. So what a pipeline reads from another one does not change until it runs chartbook update. Before a pin, interactively, a read pins on first use, reads the newest snapshot of a pipeline not declared, or reads a working folder when there is no snapshot, each with what it did said; a batch run refuses all but the pin, and a script in no pipeline reads the newest snapshot quietly (see :func:_read_in_a_pipeline);

  • a catalog reference — a pipeline plus a dataframe name — read by the same rules, with the catalog’s folder as the working version.

The rest of the grammar (#part, @rev, a registry prefix) is recognized and refused as not yet supported. See docs_src/design/references.md.

Finding a pipeline by name is here too, in :func:locate_pipeline: the one resolution chain, which asks the [dependencies] of the pipeline that wants to know, then the catalog. chartbook check, the index, the catalog lookups and cross-pipeline references all go through it.

class chartbook.resolve.FileLocation[source]#

Bases: chartbook.resolve.Location

An asset stored as a file, or as a glob of files.

Attributes: path: Absolute path. For partitioned data it contains glob characters. The file need not exist: a path can be asked for before anything has written to it. files: For a directory pinned from another pipeline, its parquet files its record lists, under path: each named .parquet, and each named otherwise that begins or ends as parquet does (Hive’s 000000_0), but none that is plainly not a table (a README.txt; :data:NOT_TABLES) or named as an engine’s scan passes over (., _). What a reader reads, and nothing else the folder may hold (a Finder .DS_Store, a sync service’s copy). Empty otherwise. listed: The files the record lists, by their path in the object, whether or not they are read. Empty when the record lists none (a file, a glob, a directory pinned before records listed files). A directory whose listed files are all passed over (a folder of CSVs) has listed and no files: data.path() gives the folder, and a read of it as parquet is refused (:func:nothing_to_read).

chartbook.resolve.known_as(location: chartbook.resolve.PipelineLocation, pipelines: Mapping[str, Union[str, pathlib.Path]]) → str[source]#

The ID a located pipeline has among the pipelines of one build.

A dependency’s key is a local name: one pipeline may call ../fed_yield_curve yield_curve while the catalog it is built in calls the same directory ftsfr/fed_yield_curve. Within a build the catalog’s name is the one every record uses, so a located pipeline that is one of the build’s own is known by the build’s ID for it. One that is not keeps the name it was found under.

Parameters:

  • location – A pipeline, from :func:locate_pipeline.

  • pipelines – The pipelines of the build: each ID and its directory.

chartbook.resolve.locate_pipeline(pipeline: str, *, dependencies: Optional[Mapping[str, dict]] = None, catalog: Optional[Mapping[str, Union[str, pathlib.Path]]] = None) → chartbook.resolve.PipelineLocation[source]#

Find where a pipeline is. This is the one resolution chain.

Each place a pipeline’s location can come from is asked in turn, and the first that knows the name answers:

  1. [dependencies] of the pipeline that is asking: an explicit location, written down by the project that needs it.

  2. The local catalog.

  3. (Reserved) configured registries. Nothing is asked today.

  4. Otherwise an error that lists what steps 1 and 2 do know.

At each step the name is matched as a catalog matches one (:func:chartbook.identity.match_pipeline_ref): a scoped ID exactly, a bare name if exactly one entry has it, a URL by the ID it reduces to. A bare name that fits two entries of one step is an error there; it does not fall through to the next step to be guessed at.

Nothing on disk is looked at. The caller gathers the two tables, and what comes back is where the pipeline is said to be, whether or not it is there.

Parameters:

  • pipeline – A reference to a pipeline: bare name, scoped ID or URL.

  • dependencies –

    The asking pipeline’s [dependencies], as

    func:

    chartbook.manifest.validate_dependencies returns it.

  • catalog – The catalog’s pipelines: each key and its directory.

Returns:

Where the pipeline is.

Raises:

  • PipelineNotFoundError – If no step knows it. A KeyError.

  • KeyError – If a bare name is ambiguous within one step.

  • UnsupportedRevisionError – If the reference carries @rev.

  • UnsupportedRegistryError – If it carries a registry prefix.

chartbook.resolve.nothing_to_read(location: chartbook.resolve.Location) → Optional[str][source]#

Why a parquet read of location has nothing to open, or None.

A directory pinned from another pipeline is read as the tables its record lists (:class:FileLocation); when it lists files and none is a table a read takes, the folder is not handed to the engine, which would read whatever it holds (a half-written _tmp/part.parquet). data.path() still gives the folder, for a reader of what it holds.

chartbook.resolve.parse_declared_ref(ref: Union[str, chartbook.refs.AssetRef], kind: Optional[str] = None, resolving: bool = False) → chartbook.refs.AssetRef[source]#

Parse a reference of a form that is supported today.

That is an asset of this pipeline or of another one: name, kind/name, pipeline:name or scope/pipeline:name. It is what a manifest may state and what :func:resolve resolves, and the two differ in what else they take.

A registry is refused as reserved either way, so the message can say “not yet” where the syntax is right.

A revision resolves for a model: a version of one of this pipeline’s own, model/x@7f3a9c2e41b0 or model/x@champion, or of a dependency’s, other:model/x@champion, which the lockfile pins. A manifest does not state one.

A part, dataframe#series, is the address of one column. In a manifest it would say which column something was made from, and that is refused as not yet supported. When resolving, it is refused for good: the address is for documenting the column, it has no file of its own, and ChartBook does not select columns (decided by the maintainer, 2026-10-13; docs_src/design/overview.md, step 4).

Parameters:

  • ref – The reference.

  • kind –

    The kind the caller expects; see

    func:

    chartbook.refs.parse_asset_ref.

  • resolving – Whether the reference is being resolved to where an asset is, as :func:resolve does, and not stated in a manifest.

Returns:

The parsed reference.

Raises:

  • UnsupportedRevisionError – If the reference carries an @rev that does not resolve.

  • UnsupportedRegistryError – If it carries a registry prefix.

  • UnsupportedReferenceError – If it names a part.

  • ValueError – If it does not follow the grammar, or names a kind other than kind.

chartbook.resolve.resolve(ref: Union[str, chartbook.refs.AssetRef], *, kind: Optional[str] = None, pipeline: Optional[str] = None, catalog_path: Optional[Union[str, pathlib.Path]] = None, start_dirs: Iterable[Union[str, pathlib.Path]] = ()) → chartbook.resolve.Location[source]#

Resolve a reference to the location of the asset it names.

This is the one resolver. With pipeline unset, ref is a reference in the grammar and resolves against the enclosing chartbook.toml: live if it is local, and to the pinned copy if it names another pipeline. With pipeline set, ref is a dataframe of that pipeline and resolves through a catalog.

Parameters:

  • ref – A reference, name, kind/name or pipeline:name; or, with pipeline, a dataframe’s name.

  • kind – The kind of asset the caller expects. A reference that names no kind takes it; one that names another kind is an error. By default a reference that names no kind is a dataframe.

  • pipeline – A pipeline reference — bare name, scoped ID, or URL — to resolve ref within, through a catalog.

  • catalog_path – The catalog to use when pipeline is given; defaults to the globally configured one.

  • start_dirs – Directories to walk up from when looking for the chartbook.toml of the pipeline the caller is in, in order of preference: what a local reference resolves against, and what decides how another pipeline’s asset is read (its pin, in a pipeline that declares it), by reference and through a catalog alike. Defaults to the current working directory.

Returns:

The asset’s location.

Raises:

  • ManifestNotFoundError – If a local reference has no enclosing chartbook.toml.

  • AssetNotDeclaredError – If a local reference names nothing the manifest declares, of that kind.

  • DependencyNotDeclaredError – If a reference names a pipeline that [dependencies] does not declare.

  • AssetNotPinnedError – If another pipeline’s asset has no pinned copy: there is no pin, or the store does not have its bytes.

  • UnsupportedReferenceError – For reserved reference syntax.

  • CatalogNotConfiguredError – If a catalog is needed and none is configured.

  • KeyError – If the pipeline or dataframe is not in the catalog.
