chartbook.migrate#

Moving a store from ChartBook 0.2’s layout to 0.3’s: chartbook store migrate.

ChartBook 0.2 kept each asset as one object, a folder named by its hash (objects/sha256/7f/3a9c…/), and each snapshot’s record under its commit (snapshots/<commit>/<name>/<time>.json). 0.3 keeps a folder for each pipeline, a folder for each snapshot in it, and each file once (:mod:chartbook.store). A store is moved once, on one machine, after every machine that uses it has ChartBook 0.3:

  1. Each record, oldest first, becomes a snapshot’s folder in its pipeline’s folder, and its files are moved there from the objects that hold them, by renaming, so a store in a synced folder uploads nothing again. A file an earlier snapshot of the pipeline holds is kept where that one has it; bytes that two pipelines’ snapshots share are copied for the second.

  2. An object no record names (0.2 pinned a git dependency with no record) becomes an object no pipeline owns, pipelines/+unowned/<hex>/, which store gc clears once no lockfile names it.

  3. The notes of the folders snapshots were made from move to origins/; the notes of lockfiles, roots/, stay as they are.

  4. store.json says the new layout, and the old folders go. A record is left where 0.2 looks for them, which 0.2 reports as one it cannot read, so that a machine still on 0.2 says so rather than that the store is empty.

A hash a 0.2 record gives is taken as it is: only the files of a glob and the documents, whose records list no hash for each file, are read. What is moved is noted first in tmp/migrate.jsonl, so that a migrate cut short is run again and goes on where it stopped. The design is “Moving a store from v1 to v2” in docs_src/design/plan-0.3.0.md.

class chartbook.migrate.MigrationPlan[source]#

What moving a store would do; nothing is moved.

Attributes: root: The store’s folder. layout: The layout its store.json names; None when it has none. records: The 0.2 records, in the order they are moved: oldest first. objects: How many objects the store holds. unowned: The objects no record names, which become objects no pipeline owns. size_bytes: The size of everything that is moved. to_read: How many bytes are read to hash them: a glob’s files and the documents, whose records give no hash for each file. shared: How many objects two pipelines’ records name, copied for the second. done: Records already moved by a migrate that was cut short. lost: The parts of records whose objects 0.2 had lost already: the records name them still, as they did. unfinished: Whether a migrate cut short after it switched the marker left the old folders: the next run removes them.
