chartbook.versions#

Versions of a catalog’s pipelines: each snapshot in the store rendered as its own site.

A catalog shows every version of every pipeline it lists (docs_src/design/versioned-catalog.md): the working version, the pipeline’s folder as it is, which is what the catalog’s own pages show; and every snapshot of it in the store, each a version its owner declared ready. A snapshot holds what its site needs (:func:chartbook.snapshot.materialize), so each is laid out from the store alone and built as the pipeline’s own site, in a process of its own, with the site tool its manifest names.

Whose files these are. A store may be one a team shares, and anyone who can write it can put a snapshot in it. So a version’s build runs as a build of files that are not the user’s own (:func:chartbook.config.untrusted_source): templates in Jinja’s sandbox and none from the project, only pages and pictures from its site folder, no page taking in a file from outside the site, never a notebook run, and a time limit. Every name in a record that becomes a folder is checked first (:func:version_name, :func:slug).

A snapshot never changes, so its site is built once and kept on this machine, under versions/ in the cache (:func:chartbook.config.get_cache_path), keyed by ChartBook’s version and a fingerprint of its code, so that a change to ChartBook builds it again; a catalog build copies it into the site at :func:site_path. One that cannot be built gets a page that says why, so that a link to it never leads nowhere. The versions are separate sites, so the catalog’s search finds the working versions only.

chartbook.versions.add_to_site(index: dict, html_dir: pathlib.Path, store=None, echo=print, rendered_by_moment: dict | None = None) → list[chartbook.versions.Rendered][source]#

Put the site of every snapshot a catalog’s index lists into its rendered site.

Each is built once on this machine and kept (:func:render), and copied here to :func:site_path under html_dir. A version’s folder that the index no longer lists, its snapshot removed by store gc, is removed, so that an incremental build does not go on serving it. The store is read once; a record that cannot be read is left out, as the index left it out. A version that could not be built is said in one line.

chartbook.versions.fingerprint() → str[source]#

ChartBook’s version and a fingerprint of its code: what a kept site was built with.

From the names, sizes and times of the package’s files, so a change to ChartBook (an upgrade, or an edit to an install from source) builds the versions again, and an unchanged one never does.

chartbook.versions.forget(taken) → bool[source]#

Clear the sites kept on this machine of a snapshot that is gone; True if there were any.

store gc calls this for each snapshot it removes, so the cache holds no site of a version no catalog will show again.

chartbook.versions.render_listed(index: dict, store=None, echo=print) → dict[source]#

Build (or find kept) the site of every snapshot a catalog’s index lists, and say on each entry whether it was built.

Called before the catalog’s pages are written, so that a page links to a version’s page only when its site was built, and otherwise to the page that says why (rendered on each snapshots entry). A snapshot that has left the store since the index was made (a gc elsewhere) is dropped from its record, so that nothing links to it. A version that could not be built is said in one line.

Returns:

Each version built or found, by (pipeline, commit, made_at): the snapshot and its :class:Rendered, for

func:

add_to_site to copy.

chartbook.versions.version_name(commit: str, made_at: str) → str[source]#

The name of a version’s folder: the commit’s start and when the snapshot was made.

4f2a91c-20261013T182205.123456Z. One commit may have several snapshots, a pull script having brought other data; the time tells them apart.

Raises:

ValueError – If the commit is not a full commit hash or the time is not one a snapshot writes: a record written to mislead, whose values would otherwise become folder names.
