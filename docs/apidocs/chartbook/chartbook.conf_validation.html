chartbook.conf_validation#

Security validation for user-provided configuration values.

This module provides validation for values that will be inserted into conf.py templates. Since conf.py is executed as Python code by Sphinx, all user input must be validated to prevent code injection attacks.

class chartbook.conf_validation.SiteConfig[source]#

Validated site configuration for conf.py template rendering.

All string values are validated against security patterns to prevent Python code injection when rendered into conf.py templates.

chartbook.conf_validation.built_nothing(manifest: dict, missing_files: list) → bool[source]#

Whether the missing files are every output of one pipeline, and nothing else.

That is a pipeline that has not been built yet: a project just made by chartbook init, or a fresh clone, whose build makes its data, charts, notebooks and models. A pipeline that has some of them and lacks others has been built, and what it lacks is a mistake to report, as is a missing write-up, note or README, which nothing builds.

Parameters:

  • manifest (dict) – The manifest dictionary from chartbook.toml.

  • missing_files (list[MissingFile]) – What :func:validate_source_files found missing.

Return type:

bool

chartbook.conf_validation.validate_source_files(manifest: dict, base_dir) → list[source]#

Validate that all source files referenced in the manifest exist.

Checks for the existence of:

  • Dataframe files (path), in any format a dataframe is read in; the format and its read_options are checked when the manifest loads (:func:chartbook.formats.check_entry)

  • Dataframe documentation files (docs_path, when mode=“path”)

  • Chart HTML files (path)

  • Chart documentation files (docs_path, when mode=“path”)

  • Notebook files (path)

  • Note markdown files (path)

  • Model files or directories (path), metrics files (metrics_path) and write-ups (docs_path)

  • The files of a files asset (path: a file, a folder that holds at least one file, or a glob that matches one) and its write-up (docs_path)

  • Each pipeline’s README (project.readme)

  • User-specified logo and favicon files

Parameters:

  • manifest (dict) – The manifest dictionary from chartbook.toml.

  • base_dir (Path) – The base directory of the project.

Returns:

List of MissingFile objects for any files that don’t exist.

Return type:

list[MissingFile]
