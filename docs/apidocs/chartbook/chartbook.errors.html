chartbook.errors#

User-friendly error handling for chartbook CLI.

This module provides structured error types and formatting utilities that produce readable, actionable error messages for CLI users.

exception chartbook.errors.AssetNotDeclaredError(name: str, manifest_path: pathlib.Path, declared: dict[str, list[str]], kind: str = DEFAULT_KIND, example_path: Optional[str] = None)[source]#

Bases: LookupError

Raised when a pipeline’s chartbook.toml declares no such asset.

The manifest is the single source of truth for where assets live, so a path is only handed out for a name it declares. The message says which table to add, or, if the name is declared as another kind of asset, how to refer to that.

Attributes: name: The asset name that was asked for. kind: The kind of asset that was asked for. manifest_path: The chartbook.toml that was searched. declared: The asset names it does declare, by table.

exception chartbook.errors.AssetNotPinnedError(asset: str, reason: str, message: str)[source]#

Bases: LookupError

Raised when another pipeline’s asset has no pinned copy to resolve to.

A reference to another pipeline’s asset resolves to the copy that chartbook.lock pins, in the store, and never to that pipeline’s working directory. So there has to be a pin, and its bytes have to be in the store. The message says which is missing and what to run.

Attributes: asset: The asset’s ID, as the lockfile would have it. reason: What is missing: "no_lockfile", "not_in_lockfile", "not_built", "not_in_store", "not_synced" (the store has the object, and not all of its bytes yet), "no_snapshot" (nothing to pin from), "working" (a batch run does not read a working folder), "in_source" (a table the pinned snapshot did not write out), or "no_pipeline" (a batch run outside any pipeline, where nothing records a read).

exception chartbook.errors.DependencyNotDeclaredError(reference: str, pipeline: str, manifest_path: pathlib.Path, declared: list[str], found_at: Optional[tuple[str, str]] = None, known: Mapping[str, Optional[str]] = {})[source]#

Bases: LookupError

Raised when a reference names a pipeline that is not a declared dependency.

A pipeline may read only from the pipelines its [dependencies] declares, so that what it depends on can be read off its manifest without running anything. The message says what to add; and when the name is a declared or known pipeline’s but for the case of its letters (Acme/Rates for acme/rates), it says so, since a scope derived from a remote is in lowercase and nothing is matched by guessing.

Attributes: reference: The reference that was asked for, as text. pipeline: The pipeline it names. manifest_path: The chartbook.toml that does not declare it. declared: The dependencies it does declare.

Initialization

Parameters:

  • found_at – Where the catalog says the pipeline is, as its key there and its folder relative to the manifest’s, if it does.

  • known – Pipeline IDs known here besides the declared keys, each with the key of the declared dependency it is the ID of (rates = { id = "acme/rates" }, a folder’s own ID), or None for one the lockfile pins or the store has a snapshot of. Only to suggest from.

exception chartbook.errors.VersionNotFoundError(asset: str, rev: str, reason: str, message: str)[source]#

Bases: LookupError

Raised when a reference names a version of an asset that cannot be found.

A version is made by a snapshot (chartbook run --snapshot) and is named by the start of its content hash, model/x@7f3a9c2e41b0, or by a label the manifest gives it, model/x@champion.

Attributes: asset: The asset’s reference, without the revision. rev: The revision that was asked for. reason: What is wrong: "no_such_version", "ambiguous" or "not_in_store".

Initialization

Initialize self. See help(type(self)) for accurate signature.
