chartbook.formats#

The formats a dataframe’s file can be in, and the one reader of them.

A dataframe that is a file is stored as parquet, CSV (or TSV), JSON lines (NDJSON, gzipped or not) or Arrow IPC (Feather). Its entry may say which::

[dataframes.releases]
path = "./_data/releases/*.jsonl.gz"
format = "jsonl"                                # else the path's ending says
read_options = { schema_overrides = { id = "String" } }

With no format, the ending of the path says it (:data:ENDINGS), and a path whose ending names none, a folder among them, is parquet. A glob is read as its ending says, and a folder as the files in it of its format. read_options go to the reader of a CSV or JSON lines file, by polars’ names; :data:READ_OPTIONS lists the ones taken, each of which DuckDB is given too, under its own name and so that it means the same, so that data.sql() reads a file as data.load() does.

This module is where a file becomes a table. data.load() in every format= it offers, data.sql() and data.ref(), the dataframe’s page, the data glimpses and the data dictionary all read through it, so each reads a file as the others do. Hashing, snapshots and pins do not come into it: they keep bytes, whatever the bytes are.

chartbook.formats.arrow_dataset(location)[source]#

An Arrow IPC file, glob or folder as a pyarrow dataset, for DuckDB to scan.

DuckDB has no reader of Arrow IPC files of its own; it reads a dataset lazily, as it would a file, taking only the columns and rows a query asks for. A glob’s or a folder’s Hive keys below it are columns (:func:_partitions), of the types and in the places data.load() gives them; a key’s value is in place of a file’s own column of its name, as it is in polars’ Hive read. A file’s path gives none. Text is plain string, a dictionary’s too: polars writes string_view, and the filter DuckDB hands a dataset in a join has no kernel for it.

Raises:

FileNotFoundError – If there is no file to read.

chartbook.formats.handed(location)[source]#

What DuckDB is handed of a file it is given no reader of, or None: what data.sql() registers in its place.

An Arrow IPC file, which DuckDB has no reader of its own for, is a pyarrow dataset (:func:arrow_dataset). A JSON lines file with schema_overrides is the frame polars reads of it: DuckDB’s casts round, trim and parse text otherwise than polars’, and its reader finds dates in text that an override to String would then give back rewritten, so it is handed the values data.load() gives.

chartbook.formats.handed_name(location) → str[source]#

The name what DuckDB is handed of a file goes by in SQL.

One per file and its reading, the same each call, so that a source’s engine keeps one view of it and not one a call.

chartbook.formats.scan(path: Union[str, pathlib.Path], format: Optional[str] = None, read_options: Optional[Mapping] = None, *, files=(), listed=(), where: Optional[str] = None, public: bool = False)[source]#

A dataframe’s file as a polars LazyFrame, read as its format is.

Parquet with pl.scan_parquet, CSV with pl.scan_csv, JSON lines with pl.scan_ndjson and Arrow IPC with pl.scan_ipc; a glob or a folder as one frame. Hive’s key=value folders are columns for parquet and Arrow IPC, those below a folder and not above it; polars reads no such columns from CSV or JSON lines, and DuckDB is told not to either. The types of a CSV or JSON lines file are inferred from its first :data:SAMPLE_ROWS rows, as DuckDB infers them, or infer_schema_length; each JSON lines file of a glob or a folder from its own, so that a field the later ones bring is kept. A CSV file’s schema_overrides are the types it is parsed as, in DuckDB too; a JSON lines file’s are cast to after it is read (:func:_cast), and DuckDB is handed what is read here (:func:handed). A CSV file with no header has its columns named column_1, column_2, …

The schema is read here, so that a file that is not of its format is said now, by name: the footer of a parquet or Arrow IPC file, the first rows of a CSV or JSON lines one. A gzipped file is decompressed whole, in memory, each time it is read, here included.

Parameters:

  • path – The file, glob or folder.

  • format – The entry’s format, if it has one.

  • read_options – The entry’s read_options, if it has them.

  • files – For a folder pinned from another pipeline, the parquet files its record lists (:class:chartbook.resolve.FileLocation).

  • listed – And every file it lists, by its path in the folder.

  • where – What a message names first: "Dataframe 'rates'".

  • public – Whether a message is for a page, which names the file by its name alone: a machine’s paths belong on no page.

Raises:

  • FileNotFoundError – If the file is not there, or a glob matches no file.

  • UnreadableTableError – If it cannot be read as its format, a folder holds no file of it, or schema_overrides names a column the file does not have.

  • ValueError – If the format or an option is not one ChartBook reads.

  • RuntimeError – If a folder’s Hive keys are to be read and no temporary folder can be written to (:func:_partitions).

chartbook.formats.sql(location) → str[source]#

A file as DuckDB reads it in SQL: read_parquet('…'), read_csv('…', …) or read_json('…', …).

A folder of parquet is its parts, with the Hive keys below it as polars reads them. A CSV or JSON lines file is given its read_options under DuckDB’s names, and what DuckDB would otherwise guess is said as polars reads it: the separator, the header, the columns’ names where polars’ are not DuckDB’s, the quote and its escape, an empty field as null and a quoted empty one as empty, and the rows its types are inferred from (:data:SAMPLE_ROWS). It has no Hive columns, as polars reads none, and the files of a JSON lines glob or folder are joined by name. What is left to inference is DuckDB’s: it finds dates in text, where polars leaves text.

Raises:

ValueError – For a file DuckDB is handed rather than given a reader of (:func:handed): an Arrow IPC file, which DuckDB has no reader of its own for, or a JSON lines file with schema_overrides; or a folder with no file of its format.
