chartbook.assets#

Assets: everything a pipeline declares, addressed one way.

An asset is something chartbook.toml declares: a dataframe, a chart, a notebook, a note, a model or a files asset. Each is addressed by a reference. Within the pipeline you are in, that is the asset’s name, with its kind in front unless it is a dataframe::

from chartbook import assets

assets.path("treasury_rates")        # [dataframes.treasury_rates]
assets.path("chart/yield_curve")     # [charts.yield_curve]
assets.path("notebook/analysis")     # [notebooks.analysis]
assets.path("note/methodology")      # [notes.methodology]
assets.path("model/rate_forecaster") # [models.rate_forecaster]
assets.path("file/filings")          # [files.filings]

An asset’s path may be a folder or a glob. :func:files gives the files themselves, sorted, and :func:index a table of them, with their sizes and hashes, to choose from before opening any::

assets.files("file/filings")         # [Path(".../2024/10-K.htm"), ...]
assets.index("file/filings")         # a LazyFrame: path, size_bytes, sha256

The kind may be given as an argument instead, which reads better when the name is in a variable. It says what you expect: a reference that names no kind takes it, and one that names a different kind is an error::

assets.path("yield_curve", kind="chart")       # the same chart
assets.path("chart/yield_curve", kind="chart") # the same chart
assets.path("yield_curve")                     # a *dataframe* called yield_curve

Data is the common case, so it gets the short spelling here and its own front door: :func:chartbook.data.path is this function for dataframes only, and :func:chartbook.models.path is this function for models only.

A reference can also be built and passed as an object, :class:AssetRef, which is what :func:parse returns and what ChartBook carries internally::

ref = assets.parse("chart/yield_curve")
ref.kind, ref.name                   # ("chart", "yield_curve")
assets.path(ref)

An asset of another pipeline has that pipeline’s name in front::

assets.path("fed_yield_curve:treasury_rates")
assets.path("fed_yield_curve:chart/curve_today")

The pipeline must be one that [dependencies] declares, and the path is that of the copy chartbook.lock pins, in the store. It is not the other pipeline’s working directory, so what it holds does not change until you run chartbook update. Read it; do not write to it.

The full grammar, [registry/][scope/]pipeline:[kind/]name[#part][@rev], is specified in docs_src/design/references.md. A part, a revision and a registry parse, and are refused as not yet supported.

chartbook.assets.files(ref: Union[str, chartbook.refs.AssetRef], kind: Optional[str] = None, project_dir: Optional[Union[str, pathlib.Path]] = None) → list[pathlib.Path][source]#

Get the files of an asset: the file, a folder’s files, or a glob’s matches, sorted.

from chartbook import assets for path in assets.files(“filings:file/earnings_releases”): # doctest: +SKIP … records = read_one(path)

The asset is found as :func:path finds it, and its files are the ones its content hash is made of (:mod:chartbook.hashing): every file under a folder or matched by a glob, but .DS_Store and the few others operating systems write by themselves. Of another pipeline’s asset they are the files of the pinned copy, as its record lists them. They are sorted by their path inside the asset, so a dataset of a file a year is read in order of the years.

It works for every asset with files: a files asset, a dataframe of many parts (to read one at a time), a model that is a folder.

Parameters:

  • ref – A reference to the asset, as for :func:path.

  • kind – The kind of asset expected, as for :func:path.

  • project_dir – Where to look for the pipeline, as for :func:path.

Returns:

The absolute path of each file.

Raises:

  • FileNotFoundError – If nothing is there: the asset is not built.

  • TypeError – If the asset is a table or a query in a source.

  • AssetNotDeclaredError – As for :func:path, and the rest of its errors.

chartbook.assets.index(ref: Union[str, chartbook.refs.AssetRef], kind: Optional[str] = None, project_dir: Optional[Union[str, pathlib.Path]] = None)[source]#

Get a table of an asset’s files, one row per file, to choose from before opening any.

import polars as pl from chartbook import assets chosen = ( … assets.index(“filings:file/earnings_releases”) … .filter(pl.col(“year”) >= “2020”) … .collect() … ) # doctest: +SKIP

The columns are path (the file, as :func:files gives it), size_bytes, sha256 (the file’s hash, in hex), and then the key of each key=value folder the files are in, as text: filings/year=2024/q=1/x.htm has year "2024" and q "1". The rows are in the order :func:files gives.

Of another pipeline’s asset, every file’s size and hash come from the record the store keeps of it, and nothing is read. Of this pipeline’s, the files are hashed, and a file is read again only when it has changed (a hash cache in this machine’s cache, ~/.chartbook/cache/hashes).

Parameters:

  • ref – A reference to the asset, as for :func:path.

  • kind – The kind of asset expected, as for :func:path.

  • project_dir – Where to look for the pipeline, as for :func:path.

Returns:

A polars.LazyFrame.

Raises:

  • FileNotFoundError – If nothing is there: the asset is not built.

  • TypeError – If the asset is a table or a query in a source.

  • AssetNotDeclaredError – As for :func:path, and the rest of its errors.

chartbook.assets.path(ref: Union[str, chartbook.refs.AssetRef], kind: Optional[str] = None, project_dir: Optional[Union[str, pathlib.Path]] = None) → pathlib.Path[source]#

Get the path of an asset: this pipeline’s own, or a pinned copy of another’s.

The enclosing chartbook.toml is the single source of truth for where an asset lives, so code can ask for the path rather than repeat it:

from chartbook import assets fig.write_html(assets.path(“chart/yield_curve”)) # doctest: +SKIP

and a build definition can use the same call for what it reads and what it writes. The path is whatever path the entry declares, made absolute; nothing checks that the file exists, so a target can be named before it is built.

Each kind of asset has its own names: [dataframes.gdp] and [charts.gdp] are two assets, gdp and chart/gdp. Asking for a name its table does not declare raises immediately, naming the table to add, or saying what kind of asset the name is declared as.

This is a convenience, never a requirement. A script that hardcodes the same path, in any language, works just as well; chartbook path on the command line gives the same answer to a shell, Make, R or Stata.

Another pipeline’s asset is named "pipeline:name", and resolves differently on purpose. The pipeline must be declared in [dependencies], and the path returned is in the store: the copy that chartbook.lock pins, not the other pipeline’s working directory.

assets.path(“fed_yield_curve:treasury_rates”) # doctest: +SKIP

So it does not change while the other pipeline is being worked on, and moves only when you run chartbook update. It must have been pinned (chartbook pin), and is for reading: never write to it.

Parameters:

  • ref (Union[str, AssetRef]) – A reference to the asset: "name" for a dataframe, "kind/name" for anything else, "pipeline:name" for another pipeline’s, or an :class:AssetRef.

  • kind (Optional[str]) – The kind of asset expected: "dataframe", "chart", "notebook", "note", "model" or "file". A reference that names no kind takes this one. By default, a reference that names no kind is a dataframe.

  • project_dir (Optional[Union[str, Path]]) – Where to look for the pipeline. The enclosing chartbook.toml is found by walking up from here. By default the search starts at the calling file’s directory, then falls back to the current working directory.

Returns:

The absolute path of the asset (it may contain glob characters for partitioned data; :func:files gives the files).

Return type:

Path

Raises:

  • AssetNotDeclaredError – If the manifest declares no such asset.

  • DependencyNotDeclaredError – If the reference names a pipeline that [dependencies] does not declare.

  • AssetNotPinnedError – If another pipeline’s asset has no pinned copy in the store.

  • ManifestNotFoundError – If no chartbook.toml encloses the starting directory.

  • KindMismatchError – If the reference names a kind other than kind.

  • ValueError – If the reference does not follow the grammar, uses syntax that is reserved and not yet supported, or the entry has no path.
