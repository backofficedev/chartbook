chartbook.models#

Models: the front door for trained models a pipeline declares.

A model is a file, or a directory of files, that a pipeline produces and declares in [models]. ChartBook records where it is, what it was trained on and its scores. It does not know what is inside: it never loads, runs or serves a model, and it imports no machine-learning framework. Loading is one line of your own code::

import joblib
from chartbook import models

model = joblib.load(models.path("rate_forecaster"))

Every function here takes a model and nothing else, as

mod:

chartbook.data does for dataframes. :mod:chartbook.assets is the general module.

Versions. A version of a model is made by a snapshot (chartbook run --snapshot): the first snapshot that holds new bytes for the model. It is named by the start of its content hash, so the name is the same on every machine and every branch, and a label in the manifest gives it a name people use::

[models.rate_forecaster.aliases]
champion = "7f3a9c2e41b0"

models.path("rate_forecaster")             # what is in the folder now
models.path("rate_forecaster@7f3a9c2e41b0")     # that version, in the store
models.path("rate_forecaster@champion")    # the version the label points at
models.versions("rate_forecaster")         # all of them, oldest first

The design, including what is deliberately not done, is docs_src/design/models.md.

class chartbook.models.Version[source]#

One version of a model: what a snapshot kept of it.

Attributes: name: The version’s name: the start of its content hash, as models.path("x@<name>") takes it. content_hash: The model’s whole content hash. made_at: When the snapshot that made it was made, in UTC. commit: The commit the pipeline was at: which code trained it. labels: The labels that point at it in [models.x.aliases]. metrics: Its scores, as the metrics file had them then. inputs: What the pipeline was pinned to then: which data. trained_on: The content hash of each trained_on input when the version was first made, by the input’s ID: exactly which data made it. built_by_run: Whether ChartBook ran the build in the command that made the snapshot.

chartbook.models.path(ref: Union[str, chartbook.refs.AssetRef], project_dir: Optional[Union[str, pathlib.Path]] = None) → pathlib.Path[source]#

Get the path the manifest declares for a model of the current pipeline.

from chartbook import models models.path(“rate_forecaster”) # doctest: +SKIP

This is :func:chartbook.assets.path with kind="model": it answers for models and nothing else. The path is the model file, or the directory that holds the model’s files. Nothing checks that it exists, so training code can ask where to write before anything is there.

A model of another pipeline is named with the pipeline in front, models.path("forecasting:rate_forecaster"), and is the copy that chartbook.lock pins; see :func:chartbook.assets.path.

A version of one of this pipeline’s models is named after @: models.path("rate_forecaster@7f3a9c2e41b0"), by the start of its content hash, or models.path("rate_forecaster@champion"), by a label of [models.rate_forecaster.aliases]. That path is in the store, is read-only, and does not change.

Parameters:

  • ref (str) – The model’s name: its key in [models].

  • project_dir (Optional[Union[str, Path]]) –

    Where to look for the pipeline, as for

    func:

    chartbook.assets.path.

Returns:

The absolute path declared for the model.

Return type:

Path

Raises:

  • AssetNotDeclaredError – If the manifest declares no such model.

  • ManifestNotFoundError – If no chartbook.toml encloses the starting directory.

  • VersionNotFoundError – If the reference names a version that is not on this machine.

  • ValueError – If the reference names another kind of asset, uses reserved syntax, or the entry has no path.

chartbook.models.read_metrics(metrics_path: Union[str, pathlib.Path]) → dict[source]#

Read a model’s metrics file: one flat JSON object of scores.

::

{ "rmse": 0.214, "mae": 0.171, "n_train": 5120, "n_test": 1280 }

Scores are in a file, not in chartbook.toml, because they are an output: they change every time the model is retrained.

Parameters:

metrics_path – The file a model’s metrics_path names.

Returns:

The scores, by name.

Raises:

  • OSError – If the file cannot be read.

  • ValueError – If it is not a flat JSON object whose values are numbers, strings or booleans.

chartbook.models.staleness(directory: Union[str, pathlib.Path], model_id: str, entry: dict, store=None) → Optional[chartbook.models.Staleness][source]#

Say whether a model is out of date: trained on inputs that have moved.

The model file’s bytes are a version, if some snapshot of the pipeline first held them; that snapshot recorded the content hash of each trained_on input at the time. Those are compared with the inputs now. The answer is None when nothing can be said: no model file, no snapshot holding these bytes, or no inputs recorded.

Parameters:

  • directory – The pipeline’s folder.

  • model_id – The model’s key in [models].

  • entry – Its manifest entry, with path.

  • store – The store; this user’s by default.

chartbook.models.versions(ref: Union[str, chartbook.refs.AssetRef], project_dir: Optional[Union[str, pathlib.Path]] = None) → list[chartbook.models.Version][source]#

List the versions of a model of the current pipeline, oldest first.

from chartbook import models [v.name for v in models.versions(“rate_forecaster”)] # doctest: +SKIP [‘7f3a9c2e41b0’, ‘b2c91d0a77f3’]

A version is made by a snapshot, so these are the versions on this machine: the ones in its store.

Parameters:

  • ref – The model’s name: its key in [models].

  • project_dir – Where to look for the pipeline, as for :func:path.

Raises:

  • AssetNotDeclaredError – If the manifest declares no such model.

  • ManifestNotFoundError – If no chartbook.toml encloses the starting directory.

chartbook.models.versions_in(directory: Union[str, pathlib.Path], model_id: str, aliases: Optional[dict] = None, store=None) → list[chartbook.models.Version][source]#

Every version of a model of the pipeline in a folder, oldest first.

Empty if the pipeline is not in a git repository, or has no snapshot that holds the model: there is nothing to list.

Parameters:

  • model_id – The model’s key in [models].

  • aliases – The model’s aliases table, to say which labels point at which version.

  • store – The store; this user’s by default.
