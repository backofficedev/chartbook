chartbook.indexdiff#

A diff of two indexes: what changed between two builds, for a reviewer.

chartbook docs generate writes index.json beside the site: every pipeline, dataframe, chart, notebook, note and model, with a content hash for each. Two of those files, from two builds, say what a change did without anyone opening the site: which data moved, which assets were added or taken away, which pins moved, which model got a new version or lost a label, which model is now out of date. This is the first reader of the index (docs_src/design/index-schema.md, “What this unblocks”): a build diff, for reviewing what changed, including what automated tooling changed.

The two indexes are compared as published: local absolute paths are left out of both, so a full index from a build directory and the published one beside the site compare as equals, and generated_at is ignored. Records are matched by kind and ID. The envelope is compared too: a different root or schema is said first, since it means the two may not be the same site, or not written the same way.

Two things the diff cannot tell apart from a change, and says so in the docs: a chart file that a renderer writes differently each time (Plotly embeds a fresh id unless given div_id; ChartBook’s own plotting helpers give one; an executed notebook’s HTML carries ids and times from its run), and a model’s versions, trained_with, trained_from and stale_inputs and a catalog’s snapshots, which are read from the store of the machine that built the index.
