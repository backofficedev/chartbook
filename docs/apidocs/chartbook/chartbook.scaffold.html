chartbook.scaffold#

What chartbook init renders, and what it does after.

chartbook init renders a project from the cookiecutter template, which is the template/ folder of ChartBook’s own repository (:data:TEMPLATE_REPOSITORY, :data:TEMPLATE_DIRECTORY). It lives beside the code so that a command the template uses and the command itself change in one pull request, and so that the tests here build a freshly rendered project. It comes with the package (a wheel carries it as chartbook/template; a source checkout has it beside src/), so the template a project gets is always the one this ChartBook was made with, and rendering it needs no network (:func:find_template, :func:render).

It is rendered with cookiecutter, and .cruft.json is written as cruft writes it, naming the repository on GitHub, its template folder and the commit the template is at (:func:template_commit), so cruft update and cruft check follow the template from there; with no commit known there is no .cruft.json, and chartbook init says how to make one. cruft itself would clone the template, which a wheel’s folder is not. A source checkout renders only the files git tracks in template/, as a wheel built from it ships.

With --git it also runs git init and makes the first commit; with --github it then creates a GitHub repository and pushes that commit. These are the same three commands every time, run here through git and gh as subprocesses, with the user’s existing configuration and login.

Everything that can be checked is checked before the template is rendered (:func:preflight), so a missing tool or login fails with nothing created.

Whether commit is on GitHub, as far as the source checkout knows: True, False, or None if it cannot tell.

cruft update clones the template from GitHub, so the commit that .cruft.json names must be there. It counts as there when a branch of a remote that is :data:TEMPLATE_REPOSITORY (a fork’s is not), or a tag (a clone of one release has only that), holds it. A built package cannot tell.

chartbook.scaffold.render(output_dir: pathlib.Path, no_input: bool = False, answers: Optional[dict] = None, package_dir: Optional[pathlib.Path] = None) → chartbook.scaffold.Rendered[source]#

Render a new project from the template that came with this ChartBook, into output_dir.

The questions are asked as cookiecutter asks them (no_input takes the defaults, and answers, by name), and the template’s hooks run. The project’s environment files ask for the template’s _chartbook_version, which is this ChartBook’s version (a test keeps the two equal). Then .cruft.json is written as cruft create writes it, when the template’s commit is known; with none, there is no commit for cruft update to start from, and no file.

Raises:

  • ScaffoldError – If the template cannot be rendered from where it is (:func:template_source), or the project’s folder is there already (:class:ProjectExistsError).

  • cookiecutter.exceptions.CookiecutterException – If cookiecutter refuses otherwise, as when a hook stops it (the template’s own hooks print why).

chartbook.scaffold.template_source(package_dir: Optional[pathlib.Path] = None) → chartbook.scaffold.TemplateSource[source]#

Where the template is (:func:find_template), and the commit of ChartBook’s repository it is at.

A built package records the commit (built_from.txt, written at build time), as does an unpacked sdist, beside its modules. A source checkout is asked with git for its HEAD, without the environment’s git location variables, as other reads of a repository here are; a template/ with changes git has not committed to tracked files is at no commit (a file git does not track is never rendered, and does not count).

Raises:

ScaffoldError – For a source tree whose tracked files cannot be told: one with a .git that git cannot read (git missing, or a folder git does not trust), or one with neither a .git of its own nor the PKG-INFO of an sdist (a copy of a checkout, which may hold an .env that was never meant to be rendered).

chartbook.scaffold.write_cruft_file(project_dir: pathlib.Path, context: dict, commit: str) → pathlib.Path[source]#

Write .cruft.json as cruft create does, naming the template on GitHub.

cruft update and cruft check read it, and clone the template from

TEMPLATE_REPOSITORY at commit. It has no skip, as cruft create writes none: cruft update adds the project’s own skips to one that is there, again on every run.
