chartbook.gitcache#

Fetching a git dependency: clones kept under ~/.chartbook/git/.

A dependency may be a git repository instead of a directory::

[dependencies]
"ftsfr/ref_data" = { git = "https://gitlab.example.org/ftsfr/ref_data", rev = "v1.2" }

To pin it, ChartBook needs the repository’s files at one commit on this disk. This module gets them there and nothing more. From then on the checkout is a directory like any path dependency’s, and pinning treats it as one.

::

~/.chartbook/git/
  repos/gitlab.example.org/ftsfr/ref_data.git       one bare clone per repository
  checkouts/gitlab.example.org/ftsfr/ref_data/
    4f2a91c0…/                                      one checkout per commit
  work/gitlab.example.org/ftsfr/ref_data/
    4f2a91c0…/                                      a copy to build in, if run

Three steps, each its own method, because only the first uses the network:

fetch Bring the bare clone up to date with the repository. resolve Turn a rev (a branch, a tag, a commit, or nothing for the default branch) into the full hash of one commit. Looks only at the clone. checkout Write that commit’s files into its own directory, if they are not there. Looks only at the clone.

ChartBook runs the git on your PATH, so whatever lets you clone the repository by hand lets ChartBook: SSH keys, credential helpers, a proxy. A URL is handed to git on each call and is never written into the clone’s configuration, so a token in a URL does not end up on disk here, and a URL is shown without its credentials in every message.

A clone has what the repository commits, and no more. Built data is usually git-ignored, so a pipeline fetched this way has its code and its manifest and, typically, none of its data. What a git dependency declares and does not commit is “not built”, exactly as for a path dependency that has not been run. chartbook pin does not run it.

chartbook run does. It makes a working copy of the commit, which is the same files and writable, and runs the dependency’s build there (:meth:GitCache.work_copy), once. What that build produces can then be pinned. A file in the copy says the build has finished (:func:is_built). A dependency that has a working copy is pinned from it, since it holds everything the checkout does and whatever was built besides. The checkout itself is never written to.

work_copy(url: str, commit: str) → pathlib.Path[source]#

Make a writable copy of a commit’s files, if there is none yet.

This is where a git dependency’s build is run. It starts as the checkout’s files and keeps whatever a build writes into it, so a second run finds the first one’s work. One working copy is shared by every project of this user that depends on that commit.

Raises:

chartbook.gitcache.repository_slug(url: str) → pathlib.Path[source]#

A relative path for a repository, made from its URL: host/owner/name.

The same repository reached two ways (https://host/a/b.git, git@host:a/b) gets one path, and so one clone. A repository on this disk goes under local/, by its folder’s name and a short hash of its whole path: the path in full would make one in the cache longer than the 260 characters Windows lets git work in. Nothing of a URL’s user name or password is in it, and no component can climb out of the cache. A port stays, as host_8443, and a component with a character that is not kept gets a short hash of itself, so that two different repositories never share a clone.
