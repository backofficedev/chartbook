chartbook.data#

Data access for chartbook: where dataframes live, and loading them.

This is the front door for dataframes. Every function here takes a dataframe and nothing else; :mod:chartbook.assets is the general module, for charts, notebooks and notes as well.

Ask the manifest where a dataframe of the current pipeline belongs, instead of repeating its path in code::

from chartbook import data

# The path declared for [dataframes.repo_public] in the enclosing
# chartbook.toml; works before the file exists, so it can name a target
df.to_parquet(data.path("repo_public"))

# A throwaway directory for intermediates: _data/_scratch/ in the pipeline
raw.to_csv(data.scratch() / "raw_download.csv")

Load a dataframe by reference: one of this pipeline, or the pinned copy of one that belongs to a pipeline declared in [dependencies]::

lf = data.load("repo_public")                    # mine, as it is now
lf = data.load("yield_curve:fed_yield_curve")    # theirs, as pinned
path = data.path("yield_curve:fed_yield_curve")  # just the path

Load dataframes from registered pipelines in a catalog::

# Load as Polars LazyFrame (default)
lf = data.load(pipeline="yield_curve", dataframe="repo_public")

# Load as Polars eager DataFrame
df = data.load(pipeline="yield_curve", dataframe="repo_public", format="polars_eager")

# Load as pandas DataFrame
df = data.load(pipeline="yield_curve", dataframe="repo_public", format="pandas")

# Get just the data path
path = data.get_data_path(pipeline="yield_curve", dataframe="repo_public")

# Get documentation content
docs = data.get_docs(pipeline="yield_curve", dataframe="repo_public")

# Get path to documentation source
docs_path = data.get_docs_path(pipeline="yield_curve", dataframe="repo_public")

chartbook.data.connect(source: str, project_dir: Optional[Union[str, pathlib.Path]] = None)[source]#

The raw connection to one of this pipeline’s [sources].

from chartbook import data con = data.connect(“local”) # doctest: +SKIP con.sql(“select 1”).fetchall() # doctest: +SKIP

For a DuckDB file that is a duckdb connection, opened read-only and afresh for each call; close it when you are done, or let it go. For a :memory: source it is the one connection that source is, for the life of the process, and it is writable: such a source holds what you put in it, and nothing else. For a Databricks source it is a connection of the Databricks SQL connector, signed in as this machine says; close it when you are done. Anything ChartBook does not expose is reachable here, and the SQL you run with it is between you and the engine.

Parameters:

  • source – The source’s name in [sources].

  • project_dir – Where to look for the pipeline, as for :func:path.

Raises:

  • LookupError – If the manifest declares no such source.

  • chartbook.backends.BackendError – If it cannot be opened.

chartbook.data.get_data_path(pipeline: str, dataframe: str, catalog_path: Optional[Union[str, pathlib.Path]] = None, *, project_dir: Optional[Union[str, pathlib.Path]] = None) → pathlib.Path[source]#

Get the resolved path to a dataframe’s parquet file, through a catalog.

For glob patterns (e.g., **/*.parquet), returns a Path containing the glob pattern characters.

Func:

path supersedes this inside a pipeline: data.path("name") for its own dataframes, and data.path("pipeline:name") for the pinned copy of a declared dependency’s. This remains the way to find a dataframe through a catalog, from a notebook that belongs to no pipeline, say. It gives the file by the rules of :func:load: in a pipeline that declares the other one, its pin; otherwise the file in the pipeline’s newest snapshot in the store; with no snapshot, the file in the folder the catalog lists, with a

Class:

~chartbook.resolve.WorkingVersionWarning. Which pipeline the call is in is found as for :func:path: from the calling file first, then the working directory, so a script in a pipeline’s folder gets that pipeline’s pin wherever it is run from.

Parameters:

  • pipeline (str) – The pipeline reference — a bare name ("crsp_treasury", if unambiguous), a scoped ID ("ftsfr/crsp_treasury"), or a repository URL.

  • dataframe (str) – The dataframe identifier within the pipeline.

  • catalog_path (Optional[Union[str, Path]]) – Path to a catalog chartbook.toml or its parent directory. If None, the global default from ~/.chartbook/settings.toml is used.

  • project_dir (Optional[Union[str, Path]]) – Where to look for the pipeline the call is made from, as for :func:path.

Returns:

The resolved path to the parquet file (may contain glob characters).

Return type:

Path

Raises:

  • CatalogNotConfiguredError – If no catalog is configured, and the store has no snapshot of the pipeline.

  • AssetNotPinnedError – If the dataframe has no copy to read: no pin in a batch run, a batch run outside any pipeline, and otherwise no snapshot and no folder here.

  • KeyError – If the pipeline or dataframe is in neither the store nor the catalog.

chartbook.data.load(ref: Optional[Union[str, chartbook.refs.AssetRef]] = None, dataframe: Optional[str] = None, format: str = 'polars', catalog_path: Optional[Union[str, pathlib.Path]] = None, *, pipeline: Optional[str] = None, project_dir: Optional[Union[str, pathlib.Path]] = None)[source]#

Load a dataframe: by reference, or from a pipeline in a catalog.

By reference, with one argument. A dataframe of the pipeline you are in is loaded from where its manifest says it is: a parquet file, or a table or query in one of its [sources], in which case the source’s engine runs it and the frame is fetched whole when it is collected. A dataframe of another pipeline is loaded from the copy that chartbook.lock pins, so it does not change until you run chartbook update:

from chartbook import data mine = data.load(“term_premium”) # doctest: +SKIP theirs = data.load(“yield_curve:fed_yield_curve”) # doctest: +SKIP

The other pipeline is declared in [dependencies] and pinned with chartbook pin, or by the first read: one declared and not pinned is pinned then, to its newest snapshot, and stderr says so. One not declared is read from its newest snapshot with an

Class:

~chartbook.resolve.UnrecordedReadWarning, and one with no snapshot from its folder with a

Class:

~chartbook.resolve.WorkingVersionWarning. Under chartbook run’s build (CHARTBOOK_BATCH=1) only a pin is read. Outside any pipeline, the newest snapshot is read and nothing is said; in a batch run there, nothing is read, since nothing records it.

Through a catalog, with a pipeline and a dataframe. This reads by the same rules: its pin, in a pipeline that declares it; otherwise its newest snapshot in the store; with no snapshot, the file in the folder the catalog lists, as it is now, with a

Class:

~chartbook.resolve.WorkingVersionWarning:

lf = data.load(pipeline=“yield_curve”, dataframe=“repo_public”, … catalog_path=“/path/to/catalog”) # doctest: +SKIP

Parameters:

  • ref (Optional[Union[str, AssetRef]]) – A reference to a dataframe: "name" for one of the current pipeline, "pipeline:name" for another pipeline’s. (With dataframe also given, this is the pipeline, as it used to be the first argument.)

  • dataframe (Optional[str]) – The dataframe identifier within pipeline, to load through a catalog.

  • format (str) – Output format — "polars" (default, returns LazyFrame), "polars_eager", "pandas", or "polars-lazyframe" (deprecated alias for "polars"). Glob patterns in a dataframe’s path only support "polars" (LazyFrame).

  • catalog_path (Optional[Union[str, Path]]) – Path to a catalog chartbook.toml or its parent directory, to load through. If None, the global default from ~/.chartbook/settings.toml is used.

  • pipeline (Optional[str]) – The pipeline to load from through a catalog — a bare name ("crsp_treasury", if unambiguous), a scoped ID ("ftsfr/crsp_treasury"), or a repository URL.

  • project_dir (Optional[Union[str, Path]]) – Where to look for the pipeline the call is made from, as for :func:path. By either form, that pipeline is found from the calling file first, then the working directory, so a script in a pipeline’s folder reads by that pipeline’s rules wherever it is run from.

Returns:

The loaded dataframe in the requested format.

Return type:

pandas.DataFrame or polars.DataFrame or polars.LazyFrame

Raises:

  • AssetNotDeclaredError – If the manifest declares no such dataframe.

  • DependencyNotDeclaredError – If a reference names a pipeline that [dependencies] does not declare, in a batch run, or when it has neither a snapshot nor a folder here.

  • AssetNotPinnedError – If another pipeline’s dataframe has no copy to read: no pin in a batch run, a batch run outside any pipeline, and otherwise no snapshot and no folder here.

  • CatalogNotConfiguredError – If a catalog is needed and none is configured, and the store has no snapshot of the pipeline.

  • KeyError – If the pipeline or dataframe is in neither the store nor the catalog.

  • TypeError – If the arguments are neither one reference nor a pipeline and a dataframe.

  • ValueError – If format is not one of the supported values, or if a glob path is used with a non-LazyFrame format.

Examples

Load as a Polars eager DataFrame:

df = data.load(“yield_curve:fed_yield_curve”, … format=“polars_eager”) # doctest: +SKIP

Load as a pandas DataFrame, through a catalog:

df = data.load(pipeline=“yield_curve”, dataframe=“repo_public”, … format=“pandas”, … catalog_path=“/path/to/catalog”) # doctest: +SKIP

chartbook.data.path(ref: Union[str, chartbook.refs.AssetRef], project_dir: Optional[Union[str, pathlib.Path]] = None) → pathlib.Path[source]#

Get the path the manifest declares for a dataframe of the current pipeline.

The enclosing chartbook.toml is the single source of truth for where a dataframe lives, so code can ask for the path rather than repeat it:

from chartbook import data df.to_parquet(data.path(“merged_rates”)) # doctest: +SKIP

and a build definition can use the same call for what it reads and what it writes — file_dep and targets in a dodo.py, say. The path is whatever path the entry declares, made absolute; nothing checks that the file exists, so a target can be named before it is built.

This is :func:chartbook.assets.path with kind="dataframe": it answers for dataframes and nothing else, so a typo cannot hand back a chart’s HTML where a parquet file was meant. For a chart, a notebook or a note, use :func:chartbook.assets.path. Asking for a name that [dataframes] does not declare raises immediately, naming the table to add, rather than surfacing later as a missing file.

This is a convenience, never a requirement. A script that hardcodes the same path, in any language, works just as well; chartbook path on the command line gives the same answer to a shell, Make, R or Stata.

A dataframe of another pipeline is named with the pipeline in front, data.path("fed_yield_curve:treasury_rates"). That pipeline must be declared in [dependencies], and the path is the copy that chartbook.lock pins, in the store, not the other pipeline’s working directory; see :func:chartbook.assets.path. Read it; never write to it.

The rest of the reference grammar, asset#part and @rev, is reserved and raises “not yet supported”.

Parameters:

  • ref (str) – The dataframe’s name: its key in [dataframes]; or "pipeline:name" for another pipeline’s.

  • project_dir (Optional[Union[str, Path]]) – Where to look for the pipeline. The enclosing chartbook.toml is found by walking up from here. By default the search starts at the calling file’s directory, then falls back to the current working directory.

Returns:

The absolute path declared for the dataframe (it may contain glob characters for partitioned data).

Return type:

Path

Raises:

  • AssetNotDeclaredError – If the manifest declares no such dataframe.

  • DependencyNotDeclaredError – If the reference names a pipeline that [dependencies] does not declare.

  • AssetNotPinnedError – If another pipeline’s dataframe has no pinned copy in the store.

  • ManifestNotFoundError – If no chartbook.toml encloses the starting directory.

  • ValueError – If the reference names another kind of asset, uses reserved syntax, or the entry has no path.

chartbook.data.ref(reference: Union[str, chartbook.refs.AssetRef], project_dir: Optional[Union[str, pathlib.Path]] = None) → str[source]#

The name a dataframe goes by in SQL, for a query you run yourself.

from chartbook import data data.ref(“treasury_rates”) # doctest: +SKIP “read_parquet(‘/work/rates/_data/treasury_rates.parquet’)” data.ref(“slopes”) # doctest: +SKIP ‘(select Date, SVENY10 - SVENY02 as slope from fed_yield_curve)’

A file is read_parquet('…'), which DuckDB reads as a table. A table in a source is its quoted identifier. A query in a source is the query, in parentheses, so it stands where a table would. Paste it into SQL you run with :func:connect, or with your own tooling.

Parameters:

  • reference – The dataframe: a name of this pipeline’s, or pipeline:name for a pinned one of another’s.

  • project_dir – Where to look for the pipeline, as for :func:path.

Raises:

  • AssetNotDeclaredError – If the manifest declares no such dataframe.

  • AssetNotPinnedError – If another pipeline’s dataframe has no pinned copy.

chartbook.data.scratch(project_dir: Optional[Union[str, pathlib.Path]] = None) → pathlib.Path[source]#

Get the current pipeline’s directory for throwaway files.

Use it for intermediates that nothing else depends on: a partial download, a cache between two steps, a file you only want to look at.

from chartbook import data tmp = data.scratch() / “raw_download.csv” # doctest: +SKIP

The directory is _data/_scratch/ inside the pipeline, created on first use. What goes in it is not an asset: it is not declared in the manifest, not documented, not published, and it ignores itself in git. It is safe to delete at any time. Because it lives inside the project, two checkouts or worktrees of the same pipeline each get their own.

One thing to avoid: a dataframe whose path is a glob over all of _data/ (./_data/**/*.parquet) would pick up scratch files too.

Parameters:

project_dir (Optional[Union[str, Path]]) – Where to look for the pipeline, as for :func:path.

Returns:

The absolute path of the scratch directory, which exists.

Return type:

Path

Raises:

ManifestNotFoundError – If no chartbook.toml encloses the starting directory.

chartbook.data.sql(query: str, project_dir: Optional[Union[str, pathlib.Path]] = None)[source]#

Run SQL that names dataframes by their ChartBook references.

from chartbook import data rates = data.sql( … “select Date, SVENY10 from {fed_yield_curve} where Date >= ‘2024-01-01’” … ) # doctest: +SKIP rates.collect() # doctest: +SKIP

Each {reference} is replaced by what :func:ref gives for it, and the SQL runs in one engine: the source that the tables and queries in it live in, or a fresh in-memory DuckDB of its own when it names only files. ChartBook never parses or rewrites the SQL; what is between the braces is a reference, and everything else is yours, in that engine’s dialect. A literal brace, as in DuckDB’s {'a': 1} struct syntax or inside a string, is written twice: {{'a': 1}}. A warehouse reads its own tables only, so a query run in one names no file.

A dataframe of another pipeline, {fed_yield_curve:treasury_rates}, is the pinned copy, as everywhere else.

Parameters:

  • query – The SQL, with references in braces.

  • project_dir – Where to look for the pipeline, as for :func:path.

Returns:

A Polars LazyFrame. Collect it to run the query. An error that only running can find, such as a cast that fails on one value, is raised then with DuckDB’s message in it, as Polars’ ComputeError or as DuckDB’s own exception, by Polars version.

Raises:

  • ValueError – If the query has no reference in it, names dataframes of two different sources, or names a file alongside a source whose engine cannot read one.

  • chartbook.backends.BackendError – If the engine refuses the SQL as it binds it: a name it does not know, or SQL it cannot parse.
