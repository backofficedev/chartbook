chartbook.incremental#

Incremental builds: regenerate and re-render only what changed.

A clean build writes every page into an empty directory and has Sphinx read and render all of them. An incremental build keeps the Sphinx project (the _docs directory) from the previous build and saves work in two places:

  1. Pipelines whose inputs are unchanged are not regenerated. Each pipeline gets a fingerprint: a hash over the modification time and size of everything its pages are made from — its chartbook.toml, its src/ and docs_src/ trees, and every file its manifest declares. A pipeline whose fingerprint matches the last build is skipped, and the pages it produced then are left exactly as they are.

  2. Pages whose content is unchanged are not touched. Whatever does get regenerated is written to a staging directory and synced into the build tree file by file, comparing content. Sphinx decides what to re-read by modification time, so a page that is rewritten identically would be re-read for nothing; a page that is left alone is not.

The fingerprint is modification-time based. That is the same notion of “changed” the rest of ChartBook uses for now; the build record designed in docs_src/design/asset-graph.md replaces it with content hashes.

Nothing here schedules or runs a pipeline’s own build. This only decides which documentation pages need regenerating once asked to build them.

What one incremental build will regenerate and what it will reuse.

chartbook.incremental.pipeline_fingerprint(pipeline_id: str, pipeline_manifest: dict, salt: str = '') → str[source]#

Hash everything a pipeline’s pages depend on.

Two builds with the same fingerprint produce the same pages for this pipeline, so the second need not produce them at all.

Parameters:

  • pipeline_id – The pipeline’s ID in this build (a catalog’s key).

  • pipeline_manifest – Its loaded manifest.

  • salt – What else the pages depend on that is not a file of this pipeline’s: the digest of what its provenance panels say, which read other pipelines’ records in the index.

Returns:

A hex digest.

chartbook.incremental.pipeline_input_files(pipeline_manifest: dict) → list[pathlib.Path][source]#

List every file a pipeline’s generated pages are made from.

That is: its manifest and README, the trees its write-ups and templates come from, any template override in its root, and each file an entry in its manifest declares. A declared file that does not exist yet is listed all the same, so that its appearing counts as a change.

Parameters:

pipeline_manifest – One pipeline’s loaded manifest.

Returns:

Absolute paths, sorted and without duplicates.

chartbook.incremental.same_size_and_not_newer(source_file: pathlib.Path, destination_file: pathlib.Path) → bool[source]#

Cheap sameness test for rendered output: same size, and not newer.

Used to copy built HTML to the output directory without reading every file. Sphinx rewrites a page only when it re-renders it, and a copy is always newer than its source, so an untouched page compares as the same.

chartbook.incremental.sync_tree(source: pathlib.Path, destination: pathlib.Path, preserve: Iterable[pathlib.Path] = (), same: Optional[Callable[[pathlib.Path, pathlib.Path], bool]] = None) → chartbook.incremental.SyncResult[source]#

Make destination mirror source, touching only what differs.

A file identical to its counterpart is left alone, modification time included. A file in destination with no counterpart is deleted unless it is preserved.

Parameters:

  • source – The tree to mirror.

  • destination – The tree to update in place.

  • preserve – Paths relative to destination to leave alone even though source lacks them. A directory covers everything under it.

  • same – Decides whether two existing files are identical. Defaults to a byte-for-byte comparison.

chartbook.incremental.watch(build: Callable[[], None], snapshot: Callable[[], dict], interval: float = 1.0, echo: Callable[[str], None] = print, sleep: Optional[Callable[[float], None]] = None, max_polls: Optional[int] = None) → int[source]#

Build, then rebuild whenever the project’s inputs change.

A thin polling loop: no file-system notification service, no server, no process other than this one. It ends on Ctrl-C.

A failed build is reported and the loop carries on, since the commonest cause is a file caught half-saved.

Parameters:

  • build – Runs one build. May raise, or exit, on failure.

  • snapshot –

    Returns the current state of the inputs (see

    func:

    snapshot_inputs). May raise while a manifest is mid-edit; the problem is reported once and the loop waits for it to clear.

  • interval – Seconds between checks.

  • echo – Receives progress lines.

  • sleep – Waits between checks. Defaults to time.sleep.

  • max_polls – Stop after this many checks. None means until Ctrl-C.

Returns:

The number of builds run, including the first.
